# استراتینو — پنل مدیریت استراتژیک

آماده‌سازی انتشار: [وضعیت کارهای پیش از خرید سرور](docs/runbooks/PREPARATION_STATUS_FA.md) و [راهنمای استقرار و بازیابی](docs/runbooks/PRODUCTION.md). بررسی آفلاین با `npm run check:deployment` انجام می‌شه؛ این فرمان Docker اجرا نمی‌کنه. فایل‌های محیط توسعه، تنظیمات انتشار واقعی نیستن.

## مسیر محصول جدید: استراتینو / Stratino

نام محصول استراتینو است. [فهرست ۵۲ تسک اولویت‌دار و تفصیلی](docs/backlog/README.md) و [نقشه پیگیری GitHub](https://github.com/Hamrez95/StrategicManagementPanel/issues/53) ترتیب توسعه را مشخص می‌کنند. رابط React + TypeScript + Vite به API مبتنی بر Django و PostgreSQL متصل است؛ مسیر اجرای محلی و مرزهای بررسی‌شده در [راهنمای اجرای کامل محلی](docs/LOCAL_NATIVE.md) ثبت شده‌اند. نسخهٔ نمونه در `/prototype/` حفظ شده است.

`npm ci` و `npm run build` کل خروجی را می‌سازند؛ `npm run dev` توسعه React را روی localhost:5173 اجرا می‌کند. راهنما و محدودیت‌های auth در [پایه React](docs/REACT_FOUNDATION.md) ثبت شده‌اند؛ مسیر حساب هنوز ورود واقعی ندارد و مسیر خصوصی در نبود session معتبر باز نمی‌شود.

اجزای مشترک رابط و راهنمای استفاده در [design system](docs/design/SYSTEM.md) ثبت شده‌اند؛ نمایش اجزا در توسعه با `/__dev/ui` و تست آن با `npm run test:ui` در دسترس است. این صفحه در production وجود ندارد.

برای ادامه توسعه ابتدا `AGENTS.md`، تسک انتخاب‌شده و [گردش توسعه](docs/DEVELOPMENT_WORKFLOW.md) را بخوانید. مهارت frontend-design داخل `.agents/skills/` و Graphify مخصوص Codex داخل `.codex/skills/` ثبت شده‌اند؛ [قرارداد UI/UX](docs/UX_STANDARD.md) در همه تسک‌ها اعمال می‌شود.

پروتوتایپ تعاملی فارسی و راست‌به‌چپ برای مدیر استراتژی و بنیان‌گذار استارتاپ؛ با یک شرکت کاملاً فرضی، داده نمونه، فونت محلی وزیرمتن و مسیر آموزشی از شناخت کسب‌وکار تا اجرای استراتژی.

## تجربه کاربری

- مسیر شش‌مرحله‌ای: تعریف مسئله، شناخت محیط، ارزیابی داخلی، انتخاب، اجرا و بازبینی.
- ۱۸ بخش کاری: نمای مدیریتی، مسیر شروع، پروفایل شرکت، محیط، صنعت، تحلیل داخلی، ماتریس‌ها، SWOT/TOWS، اتاق تصمیم، مالی، سناریو، اجرای ۹۰روزه، کارت امتیازی، ریسک، دفتر تصمیم، گزارش، آموزش و تنظیمات.
- ۹ ابزار ماتریسی: EFE، IFE، CPM، SPACE، BCG، IE، GE، Ansoff و Grand Strategy؛ همچنین QSPM و VRIO در بخش‌های مربوط.
- نمودار روند و هدف، رادار پنج نیرو، حباب BCG، بردار SPACE، نقشه استراتژی، نقشه حرارتی ریسک و برد اجرای برنامه.
- ویرایش وزن‌ها و امتیازها، محاسبه زنده نسبت‌های مالی و سناریو، ایجاد و ویرایش تصمیم‌ها، فرضیه‌ها، ریسک‌ها، اهداف و اقدامات.
- راهنمای زمینه‌ای با حرکت نشانگر یا فوکوس روی آیکن اطلاعات؛ توضیح کامل، فرمول، مثال، تفسیر، محدودیت و منبع با کلیک یا لمس.
- ذخیره مرورگر، پشتیبان JSON با اعتبارسنجی، چاپ گزارش/PDF، جست‌وجوی سراسری و حالت راهنمای سبک برای استارتاپ.

## اجرا و بررسی

Node.js 22.12 یا جدیدتر. کتابخانه‌های React در build بسته‌بندی می‌شوند و نیاز به CDN اجرایی ندارند؛ prototype قبلی همچنان بدون کتابخانه اجرایی خارجی کار می‌کند.

### اجرای محلی در ویندوز

در PowerShell، از ریشه ریپو اجرا کنید:

```powershell
Set-ExecutionPolicy -Scope Process Bypass
.\run-local.ps1
```

در اجرای معمولی، آخرین commit شاخهٔ `origin/main` دریافت و در worktree موقت ساخته می‌شود؛ شاخهٔ کاری و فایل‌های پروژه تغییر نمی‌کنند. منوی PowerShell فقط انگلیسی است و سه انتخاب دارد: `Admin panel`، `Website` و `Both`.

در ویندوز، اجرای پیش‌فرض حالا وب، API، PostgreSQL قابل‌حمل و صندوق ایمیل محلی را با هم بالا می‌آورد؛ Docker اجرا نمی‌شود و Windows Service نصب نمی‌شود. Python نسخهٔ 3.11 یا جدیدتر و ۶۴بیتی لازم است؛ با `-PythonPath` می‌توان مسیرش را داد. وابستگی‌های قفل‌شده و ابزارهای محلی در اولین اجرا دریافت می‌شوند. مسیر و جزئیات در [اجرای کامل محلی](docs/LOCAL_NATIVE.md) ثبت شده‌اند.

```powershell
.\run-local.ps1
```

گزینهٔ `Admin panel` مسیر `/internal/login`، گزینهٔ `Website` صفحهٔ اصلی `/` و گزینهٔ `Both` هر دو صفحه را روی یک سرور محلی باز می‌کند. API در حالت پیش‌فرض متصل است؛ برای ساخت صریح حساب مدیر محلی از `-Target admin -SetupAdmin` استفاده کن. تغییر رمز موقت و MFA همچنان الزامی‌اند. برای حذف منو، `-Target admin`، `-Target site` یا `-Target both` بدهید:

```powershell
.\run-local.ps1 -Target admin
.\run-local.ps1 -Target site
.\run-local.ps1 -Target both
```

main همیشه پس از fetch از `origin/main` اجرا می‌شود، حتی با `-Refs main` یا `-Refs origin/main`؛ در صورت خطای fetch نسخهٔ قدیمی اجرا نمی‌شود. Academy در main به‌صورت پیش‌فرض فعال است. انتخاب نسخهٔ آموزشی همچنان با پارامتر صریح ممکن است:

```powershell
.\run-local.ps1 -Version main
.\run-local.ps1 -Version academy
```

برای ref دلخواه یا اجرای چند نسخه کنار هم، از `-Refs` استفاده کنید. به‌جز main که همیشه از آخرین `origin/main` است، ref محلی بر `origin/<branch>` اولویت دارد؛ `-AcademyPreview` برای فعال‌کردن آموزش روی refهای دیگر باقی است:

```powershell
.\run-local.ps1 -Refs main, feat/stratino-academy
.\run-local.ps1 -Refs main, feature/my-change
```

با `Ctrl+C` سرورها بسته می‌شوند و worktreeهای موقت پاک می‌شوند. اجرای پروژه روی شاخه کاری فعلی اثری ندارد. برای باز نکردن خودکار مرورگر از `-NoBrowser` استفاده کنید.

در هر worktree ابتدا `npm ci` با فایل قفل همان نسخه اجرا می‌شود. Node.js حداقل 22.12 لازم است. اگر پورتی اشغال باشد، رانر پورت آزاد بعدی را انتخاب می‌کند؛ با `-FirstPort 18473` بازه شروع را تغییر دهید. آدرس فقط پس از پاسخ HTTP موفق صفحهٔ اصلی و Academy چاپ می‌شود. گزارش‌ها در پوشه موقت اختصاصی هر اجرا می‌مانند. `-SmokeTest -NoBrowser` پس از آماده‌شدن همه نسخه‌ها، سرورها و worktreeها را می‌بندد. آزمون منوی واقعی، آخرین commit، نمایش Academy روی main، مسیرهای سایت/ادمین، پورت اشغال‌شده و cleanup با `pwsh -File scripts/test-local-runner.ps1` اجرا می‌شود. برای ذخیره شاهد اجرای رانر از `-EvidencePath test-results/runner.json` استفاده کنید.

برای پیش‌نمایش صرفاً وب از `-WebOnly` استفاده کن؛ در این حالت محتوای متصل به API، ورود و ذخیره‌سازی کار نمی‌کنند. برای بررسی واقعی API و صفحهٔ راهنما می‌تونی `-VerifyApi -VerifyBrowser -NoBrowser -SmokeTest` بدی. تست‌های API از دیتابیس آزمایشی جدا استفاده می‌کنند. اجرای اصلی تا آماده‌شدن API، migrationها و بارگذاری محتوای آموزش منتظر می‌مونه؛ خطای بک‌اند رو با اجرای ناقص وب پنهان نمی‌کنه.

برای اجرای وب همراه با سرویس‌های محلی، Docker Desktop و Compose v2 را اجرا کنید و `pwsh -File run-local.ps1 -WithBackend` را بزنید؛ منوی انتخاب صفحه نمایش داده می‌شود. Python داخل کانتینر نصب می‌شود؛ نصب جدا روی میزبان لازم نیست. هر نسخه نام پروژه Compose، رمز محلی، دیتابیس و فایل مستقل دارد؛ رمزها در `.local-dev/` خارج از Git نگهداری می‌شوند. وب درخواست‌های `/api/` را به API همان نسخه می‌فرستد. آدرس وب پس از آماده‌شدن API و اعمال migration چاپ می‌شود. پورت‌های API و ایمیل به‌ترتیب از 8000 و 8025 شروع می‌شوند؛ با `-FirstApiPort` و `-FirstMailPort` قابل تغییرند.

در حالت Docker، توقف، کانتینرها و worktree موقت را جمع می‌کند و volume داده و رمز محلی را نگه می‌دارد. اجرای دوباره همان commit و جایگاه در فهرست refها، همان داده را باز می‌کند. commit جدید فضای مستقل دارد؛ انتقال داده نسخه‌های مختلف در STR-017 است. این مسیر فقط برای توسعه است؛ اتصال API و ذخیره‌سازی هر قابلیت باید طبق شواهد همان قابلیت بررسی شود.

```sh
npm run check
npm test
npm run build
```

خروجی در `dist/` ساخته می‌شود و باید با یک میزبان فایل استاتیک ارائه شود؛ بازکردن مستقیم فایل با `file://` مناسب ماژول‌ها و Service Worker نیست. برای نصب PWA به HTTPS یا localhost و مرورگر پشتیبان نیاز است.

## تنظیمات Vercel

ریپو را در Vercel Import کنید:

| گزینه | مقدار |
| --- | --- |
| Framework Preset | Other |
| Root Directory | ریشه ریپو |
| Build Command | `npm run build` |
| Output Directory | `dist` |
| Install Command | `npm install` |
| Environment Variables | لازم نیست |

`vercel.json` همین تنظیمات و هدرهای امنیتی را تعریف می‌کند. مسیرها hash-based هستند؛ همه صفحات از نقطه ورود استاتیک استفاده می‌کنند. اولین انتشار از اتصال موجود به Vercel به علت نداشتن مجوز ایجاد پروژه متوقف شد؛ هنوز URL انتشار تأییدشده‌ای ثبت نشده است.

## حدود نسخه نمونه

این نسخه نرم‌افزار سازمانی عملیاتی نیست: ورود و نقش‌های واقعی، بک‌اند، چندسازمانی، همگام‌سازی ابری، اعلان زمان‌بندی‌شده، اتصال ERP و موتور توصیه هوش مصنوعی ندارد. همه اطلاعات در همین مرورگر و همین دامنه ذخیره می‌شوند؛ پاک‌کردن داده مرورگر یا تغییر دامنه، اطلاعات را منتقل نمی‌کند. از داده حساس واقعی استفاده نکنید و پشتیبان بگیرید.

مدل‌های تحلیلی ابزار تصمیم‌سازی‌اند، نه تضمین رشد یا نسخه واحد برای همه صنایع. داده، واحد، دوره، فرضیات و محدودیت‌های هر مدل در رابط نمایش داده می‌شوند. برخی نمودارهای آموزشی، از جمله GE، نمایش کارگاهی ساده‌شده‌اند و این موضوع در همان صفحه تصریح شده است.

## ساختار و مستندات

- `src/app.js`: صفحات، فرم‌ها، رویدادها و ذخیره‌سازی.
- `src/data.js`: شرکت نمونه، محتوا، درس‌ها و منابع.
- `src/calculations.js`: محاسبات مستقل از رابط.
- `src/charts.js` و `src/styles.css`: نمودارها و طراحی واکنش‌گرا.
- `public/`: نقطه ورود، فونت، آیکن‌ها، manifest و Service Worker.
- [منطق طراحی](docs/DESIGN.md)، [روش‌شناسی و منابع](docs/METHODOLOGY.md)، [نتایج و محدودیت‌های تست](docs/VERIFICATION.md).

طراحی از وضوح ناوبری و آرامش بصری Buffer الهام گرفته، بدون کپی هویت آن. فونت [Vazirmatn](https://github.com/rastikerdar/vazirmatn) با مجوز SIL OFL در `public/assets/OFL.txt` نگهداری می‌شود.

## تجربه جدید: آموزش، ظاهر و زبان

- دکمه «آموزش این صفحه» در تمام بخش‌های کاری و ماتریس‌ها، راهنمای مرحله‌ای همان صفحه را باز می‌کند: برجسته‌سازی بخش مرتبط، مثال، دکمه قبلی/بعدی و بستن با Escape. آموزش‌ها با لمس و کیبورد هم کار می‌کنند.
- در تنظیمات، «فعال‌سازی آموزش در اپ» تمام راهنماها، علامت‌های `!` و کتابخانه آموزشی را کنترل می‌کند. در حالت حرفه‌ای، هشدارهای اعتبار داده و محاسبات باقی می‌مانند.
- تم روشن، تیره و مطابق سیستم؛ رابط فارسی RTL و انگلیسی LTR، همراه با اعداد و متن‌های نمونه به زبان انتخاب‌شده. زبان و ظاهر مستقل از داده‌های کسب‌وکار ذخیره می‌شوند. متن‌های شخصی کاربر ترجمه ماشینی نمی‌شوند؛ تاریخ موعدهای نمونه همچنان شمسی است.
- متن‌های اصلی، جدول‌ها و کنترل‌ها خواناتر شده‌اند. نمودارهای بزرگ روی موبایل با پیمایش افقی، برچسب‌های خوانا دارند.
- تصویر برداری، رسم نمودار، ورود یکپارچه صفحه و بازشدن پنجره‌ها متحرک‌اند. تنظیم «حرکت کمتر» و ترجیح کاهش حرکت دستگاه رعایت می‌شوند.
- ICP در شناخت شرکت و کتابخانه توضیح داده می‌شود: پروفایل مشتری ایده‌آل با شواهد ساخته می‌شود و نسبت عددی با فرمول ثابت نیست.

### بررسی مرورگری توسعه‌دهندگان

Playwright فقط وابستگی توسعه است؛ اجرای پنل به آن نیاز ندارد. بعد از بالا آوردن localhost:

```sh
npm ci
npx playwright install chromium
npm run test:browser
```

تست به‌طور پیش‌فرض `http://localhost:4173` را بررسی می‌کند. با متغیر `STRATEGY_URL` می‌توان آدرس دیگر داد. نتایج و تصاویر در `test-results/` ساخته می‌شوند.
