# استراتینو — قرارداد مشترک UI/UX برای تمام تسک‌ها

## جهت طراحی

هویت یک ابزار حرفه‌ای استراتژی: وضوح تصمیم، شواهد و اقدام بعدی. داشبورد از «کار بعدی مدیر» شروع شود، نه ردیف کارت KPI بی‌دلیل. صفحه عمومی می‌تواند یک نمایش زنده از تبدیل تحلیل به اقدام داشته باشد؛ پنل کاری آرام، خوانا و سریع بماند.
پیش از کدنویسی هر صفحه، یک طرح کوتاه رنگ/تایپ/چیدمان/موشن بنویس و پس از اجرا با تصویر واقعی نقد کن. منبع اجباری: `.agents/skills/frontend-design/SKILL.md`.
نمونه‌های Figma/Trello/Buffer صرفاً الگوی آشنا هستند؛ لوگو، برند، متن و ظاهر اختصاصی کپی نشود.

## معیارهای اجباری صفحه و کامپوننت

- فارسی RTL با CSS logical properties؛ مسیر LTR و i18n از آغاز. عدد نمایشی فارسی در fa و انگلیسی در en؛ واحد، دوره و ارز آشکار. ID، ایمیل، URL و مقدار API بدون فارسی‌سازی مخرب.
- فونت محلی Vazirmatn با مجوز موجود؛ بدنه هدف ۱۶px، وزن و line-height خوانا. بزرگ‌نمایی ۲۰۰٪؛ جدول داده حداقل خوانا و اسکرول در پنل خودش، نه کل صفحه.
- عرض‌های بررسی: ۳۶۰، ۷۶۸، ۱۲۸۰ و ۱۴۴۰؛ کنترل لمس هدف ۴۴px. چیدمان موبایل معنای اطلاعات را حفظ کند و صرفاً دسکتاپ کوچک‌شده نباشد.
- تم روشن/تیره/سیستم با semantic tokens و بدون flash؛ وضعیت بدون اتکا به رنگ. هدف WCAG 2.2 AA، کنتراست متن عادی ۴٫۵:۱ و اجزای ضروری ۳:۱.
- کیبورد، focus واضح، label، نام آیکن، ترتیب heading، اعلان مناسب screen reader. دیالوگ focus trap، Escape، بازگشت focus و جلوگیری از گم‌شدن فرم داشته باشد.
- loading/skeleton فقط هنگام نیاز؛ empty state با اقدام بعدی؛ error با علت قابل فهم و retry؛ success و validation آشکار؛ وضعیت permission-denied، limit و شبکه قطع نیز طراحی شود.
- فرم با خطای مرتبط به فیلد؛ جلوگیری از دوباره‌ارسال؛ حفظ متن پس از خطا. autosave وضعیت ذخیره/خطا/تعارض داشته باشد؛ در خطا هرگز پیام «ذخیره شد» نشان ندهد.
- موشن برای تغییر معنادار: باز/بسته‌شدن، جابه‌جایی و نتیجه محاسبه. بازه پیشنهادی ۱۲۰–۲۴۰ms، بدون انتظار اجباری. reduced-motion سیستم و تنظیم شخصی رعایت شود؛ تصویر و SVG خوانا و دارای جایگزین متنی باشند.
- نام Workspace همیشه آشکار؛ سوییچ پروژه خطر ذخیره در پروژه اشتباه ایجاد نکند. منوی شخصی و تنظیمات پروژه از هم جدا باشند.
- آموزش اختیاری حساب، مستقل از صحت محاسبه و پیام ایمنی. دکمه آموزش، تم، زبان و اشتراک قابل پیدا کردن باشند؛ فقط tooltip کافی نیست.
- ارتقا با توضیح ارزش و سهمیه؛ بدون urgency جعلی، هزینه مخفی، confirmshaming یا مسدودکردن خروجی داده شخصی.

## تسک‌های بدون رابط مستقیم

بک‌اند/زیرساخت باید قرارداد خطا، زمان پاسخ، دسترسی، save status و محدودیت‌های قابل فهم برای UI را مشخص کنند. «UI/UX ندارد» جای بررسی اثر بر تجربه کاربر را نمی‌گیرد؛ ساخت صفحه نمایشی برای یک تسک زیرساختی لازم نیست.

## شواهد پذیرش

در PR مسیرها، breakpointها، تم‌ها و حالت‌های بررسی‌شده را بنویس؛ تصاویر قبل/بعد برای تغییر بصری و تست کیبورد برای جریان حساس لازم است. اگر چیزی آزمایش نشده دقیق بنویس؛ برچسب «مدرن» یا screenshot به‌تنهایی آزمون مجوز و ذخیره نیست.
