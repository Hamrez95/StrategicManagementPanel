# Private document attachments

Attachments are stored under the API's private storage root. The default local backend is a filesystem storage adapter whose `url()` method is disabled; files are served only by an authenticated Workspace endpoint that checks membership and attachment state on every request. Download responses use `application/octet-stream`, `nosniff`, a restrictive content security policy, and private no-store caching.

The upload lifecycle is `reserved → uploading → quarantined → ready`; an in-flight cancellation stays quota-reserved until the stream stops. Reservation requests carry an idempotency UUID so a retry after a lost response can recover the existing slot without reserving bytes twice. The reservation locks the Workspace row and accounts for the full declared size before bytes are accepted. Per-file size, per-Workspace bytes, and active files per document are configurable through the `STRATINO_ATTACHMENT_*` and `STRATINO_WORKSPACE_FILE_QUOTA_BYTES` environment settings. File names are reduced to a safe leaf name, extensions are allowlisted, server-side signatures are checked, and SHA-256 is calculated while streaming into a random quarantine key. The configured MIME value is derived from the allowlisted extension; browser-supplied MIME is not trusted.

Only a successful ClamAV `INSTREAM` result permits an atomic same-volume move into the ready namespace. A detected threat is deleted and rejected. If ClamAV is unavailable or times out, the upload stays quarantined and cannot be downloaded; a Workspace editor can retry the scan after service recovery. Development Compose starts the pinned `clamav/clamav:1.5.4` service without publishing its daemon port and keeps signature data in a named volume. The API does not treat a missing scanner as a clean result. Production startup requires `CLAMAV_HOST` to be configured to a private scanner service.

Expired reservations and quarantined files are removed by `python manage.py cleanup_document_attachments`. The command is a dry run by default; `--apply` deletes expired records and old unreferenced files. Orphan files receive a 24-hour grace period by default (`--orphan-age-hours` can adjust it). Run the cleanup as part of operations scheduling after verifying the configured private storage root and retention policy.

Before accepting this feature, run the API attachment test class against PostgreSQL and the configured local scanner, then verify upload, scan retry, viewer download, membership revocation, quota contention, checksum stability after API/container restart, and cleanup behavior with a real private-files volume. Browser tests should cover multiple selection, progress/cancel/retry, accessible file picking, RTL/LTR, both themes, and all documented viewport widths. No server, Docker, scanner, or browser test is claimed complete by this implementation change.
