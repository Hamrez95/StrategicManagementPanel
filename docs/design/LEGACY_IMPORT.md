# انتقال پشتیبان قدیمی

## تصمیم طراحی

واردسازی در هر Workspace یک مسیر صریح و قابل بازگشت دارد: انتخاب فایل، پیش‌نمایش سمت سرور، تأیید نام Workspace مقصد، سپس ساخت یک batch تغییرناپذیر. این نسخه داده‌های نگاشت‌شده را در آرشیو خصوصی همان Workspace نگه می‌دارد تا مدل‌های دامنه در تسک‌های بعدی آماده شوند؛ رابط ادعا نمی‌کند که ابزارهای زنده از این snapshot استفاده می‌کنند.

قرارداد ورودی `royesh-strategy-v1` با نسخهٔ نگاشت ۱ اعتبارسنجی می‌شود. محاسبات QSPM، SPACE، مالی و سناریو، تصمیم‌ها، مراحل اجرا، یادداشت‌ها و فراداده مدارک در بخش‌های نام‌دار نگه داشته می‌شوند. نسخهٔ اصلی پاک‌سازی‌شده نیز همراه snapshot ذخیره می‌شود تا بازسازی ممکن بماند. دادهٔ `localStorage` پروتوتایپ خوانده یا تغییر داده نمی‌شود.

## حفاظت و بازیابی

- فایل حداکثر ۱ مگابایت است؛ JSON خراب، عدد غیرمتناهی، schema ناشناخته، عمق یا تعداد رکورد بیش از حد رد می‌شود.
- preview هیچ تغییری در پایگاه داده نمی‌دهد. ذخیرهٔ batch در تراکنش انجام می‌شود و فقط owner/editor مجاز به واردسازی است.
- کلید idempotency درخواست تکراری را قطعی می‌کند و digest یکسان در همان Workspace از ساخت نسخه فعال تکراری جلوگیری می‌کند.
- Undo، batch را از آرشیو فعال خارج می‌کند ولی دادهٔ snapshot را برای بازیابی نگه می‌دارد. owner یا ایجادکننده می‌تواند آن را undo کند.
- بایت فایل منتقل نمی‌شود. نام، نوع و اندازهٔ قابل‌شناسایی به‌عنوان metadata می‌مانند و تعداد فایل‌هایی که بارگذاری دوباره می‌خواهند در preview دیده می‌شود.
- همهٔ خواندن‌ها و نوشتن‌ها به عضویت همان Workspace محدودند و پاسخ‌ها private/no-store هستند.

## طرح رابط

صفحه در پوستهٔ موجود Workspace قرار دارد: انتخاب‌گر مقصد بیرون از فرم است و نام آن در preview دوباره نشان داده می‌شود. کارت شمارش‌ها در شبکهٔ واکنش‌گرا قرار می‌گیرد، هشدار فقدان بایت متن و نشان رنگی دارد، و حالت‌های loading، خطا، خالی، موفق و دسترسی فقط‌خواندنی از کامپوننت‌های موجود استفاده می‌کنند. برچسب‌ها فارسی/انگلیسی و جهت صفحه از تنظیم حساب می‌آیند؛ CSS از ویژگی‌های منطقی استفاده می‌کند و تم از tokenهای روشن/تیره می‌آید.

نقد طراحی پیش از screenshot اجرایی: مقصد و شمارش‌ها پیش از دکمهٔ تأیید دیده می‌شوند؛ warning فایل از فهرست عمومی جداست؛ اعمال بدون تأیید یا با تغییر Workspace انجام نمی‌شود؛ Undo دیالوگ تأیید دارد؛ دانلود و پیام خطای شبکه دسترس‌پذیرند. screenshot، breakpointها، صفحه‌کلید و تم‌ها در مرحلهٔ اعتبارسنجی نهایی پس از اجرای محلی بررسی می‌شوند.

## حدود این نسخه

Snapshot فعلاً لایهٔ سازگاری است، نه جایگزین پروفایل و ابزارهای آینده. تبدیل batch به رکوردهای زنده، import چند schema جدید و انتقال بایت فایل نیازمند قراردادهای تسک‌های بعدی و اعتبارسنجی مستقل است.
