# STR-057 — شواهد، ادعا، اطمینان توضیح‌پذیر و تازگی داده

Priority: **P0** | Epic: **MOS-TWIN** | Status: planned. Dependencies: STR-056, STR-012.

## Context / Problem

Legacy evidence/confidence labels cannot support reusable, explainable business claims or contradictions.

## Goal / User value

Persist Claim and Evidence separately with support/refutation, origin/method/sample/scope, observed/review dates and source identity. The manager reuses trustworthy business information and reaches a defensible next action with less repeated input.

## Scope / Functional requirements

- Persist Claim and Evidence separately with support/refutation, origin/method/sample/scope, observed/review dates and source identity.
- Implement ordinal confidence rubric with axis reasons, reviewer and version; legacy confidence remains reported provenance.
- Define freshness from owner review_due/context and preserve contradictory evidence and revoked source permissions.

## Non-goals

No new hosting, paid services, generic workflow DSL, graph database, arbitrary health score or opaque AI decision logic. Preserve legacy tools; no unrelated domain expansion. No decorative UI or invented production endpoint is required.

## Domain impact / Data requirements

Follow the ownership and contracts in [ARCHITECTURE](../management-os/ARCHITECTURE.md). Workspace ID and explicit venture/segment/period context, revision, canonical references and provenance are required. No second ICP/revenue/Goal copy. Any persistence/schema change needs an explicit version and compatibility/rollback plan before apply.

## Knowledge-base dependencies

- `assets/management-knowledge/evidence/evidence-model.md`
- `assets/management-knowledge/evidence/confidence-model.md`

## UX requirements / Accessibility

Return actionable bounded errors with affected IDs/fields; do not leak evidence or require managers to understand engine internals. When surfaced in UI, unknown/invalid/stale states need text and keyboard-accessible explanation, not color alone.

## AI involvement / Deterministic logic

AI has no authority in this task. Reviewed IDs, versions, permissions, derivation, formulas, gates and completion are deterministic; source prose is never eval-executed. Any later AI wording is a reviewable draft outside this scope.

## Security / Privacy

Enforce server-side membership and same-Workspace nested references on all reads/writes/import/export/jobs. Viewer cannot write; revoked membership loses access. Use redacted logs, minimal personal data and revision/idempotency protections.

## Acceptance criteria

- [ ] Given a claim with an unresolved material contradiction, reviewed confidence is at most low; essential missing dependency yields insufficient.
- [ ] Given the same interview imported twice, it is not counted as independent corroboration.
- [ ] Given stale competitor evidence or a removed member, UI/API clearly reports freshness or denies access without exposing content.

- fact vs interview axes, missing provenance, stale/future dates, duplicate external source, conflicting support/refutation, viewer and cross-tenant access.
