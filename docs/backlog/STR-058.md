# STR-058 — MetricValue و محاسبه مرجع حاشیه مشارکت

Priority: **P0** | Epic: **MOS-TWIN** | Status: planned. Dependencies: STR-054, STR-056, STR-057.

## Context / Problem

Financial formulas are research text; observed values, units and canonical calculations need a safe persisted contract.

## Goal / User value

Persist metric values and calculation runs by metric/method/variant/scope/period/unit/currency/basis with input and evidence revisions. The manager reuses trustworthy business information and reaches a defensible next action with less repeated input.

## Scope / Functional requirements

- Persist metric values and calculation runs by metric/method/variant/scope/period/unit/currency/basis with input and evidence revisions.
- Implement only MET-CONTRIBUTION-MARGIN amount using Decimal and explicit variable-cost policy; TS preview shares reviewed fixtures.
- Return unknown/invalid/not_applicable separately from zero; preserve historical snapshots and no eval execution path.

## Non-goals

No new hosting, paid services, generic workflow DSL, graph database, arbitrary health score or opaque AI decision logic. Preserve legacy tools; no unrelated domain expansion. No decorative UI or invented production endpoint is required.

## Domain impact / Data requirements

Follow the ownership and contracts in [ARCHITECTURE](../management-os/ARCHITECTURE.md). Workspace ID and explicit venture/segment/period context, revision, canonical references and provenance are required. No second ICP/revenue/Goal copy. Any persistence/schema change needs an explicit version and compatibility/rollback plan before apply.

## Knowledge-base dependencies

- `assets/management-knowledge/metrics/finance/met-contribution-margin.json`

## UX requirements / Accessibility

Return actionable bounded errors with affected IDs/fields; do not leak evidence or require managers to understand engine internals. When surfaced in UI, unknown/invalid/stale states need text and keyboard-accessible explanation, not color alone.

## AI involvement / Deterministic logic

AI has no authority in this task. Reviewed IDs, versions, permissions, derivation, formulas, gates and completion are deterministic; source prose is never eval-executed. Any later AI wording is a reviewable draft outside this scope.

## Security / Privacy

Enforce server-side membership and same-Workspace nested references on all reads/writes/import/export/jobs. Viewer cannot write; revoked membership loses access. Use redacted logs, minimal personal data and revision/idempotency protections.

## Acceptance criteria

- [ ] Given revenue 100 and reviewed variable costs 60 in identical units/period, authoritative contribution amount is 40.
- [ ] Given missing cost or mixed IRR/IRT, mismatched scope/period, no numeric result is fabricated.
- [ ] Given canonical metric exists for the current context, Journey reuses it without asking revenue again; input revision invalidates stale cache.

## Test cases

- zero, negative margin, null, nonfinite, decimal rounding, currency/period mismatch, client/server parity, foreign evidence and snapshot immutability.

Persona fixtures A (solo idea/no revenue), B (SaaS/10 staff/20 paying customers), C (ecommerce/50 staff), D (service SME/80 staff/low profit), E (manufacturing/300 staff/inventory), F (enterprise/2000 staff/execution) are context contracts, not observed user research. Apply relevant positive/negative cases and assert irrelevant inputs are suppressed.
