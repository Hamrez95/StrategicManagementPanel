## Context / Problem

Financial formulas are research text; observed values, units and canonical calculations need a safe persisted contract.

## Goal / User value

Persist metric values and calculation runs by metric/method/variant/scope/period/unit/currency/basis with input and evidence revisions. The manager reuses trustworthy business information and reaches a defensible next action with less repeated input.

## Scope / Functional requirements

- Persist metric values and calculation runs by metric/method/variant/scope/period/unit/currency/basis with input and evidence revisions.
- Implement only MET-CONTRIBUTION-MARGIN amount using Decimal and explicit variable-cost policy; TS preview shares reviewed fixtures.
- Return unknown/invalid/not_applicable separately from zero; preserve historical snapshots and no eval execution path.

## Non-goals

No new hosting, paid services, generic workflow DSL, graph database, arbitrary health score or opaque AI decision logic. Preserve legacy tools; no unrelated domain expansion. No decorative UI or invented production endpoint is required.

## STR-058-A — typed numeric observations and immutable result snapshots

Status: complete locally in `05d43d6`; STR-058-B, PostgreSQL/restore, server, Docker, browser/physical acceptance and remote merge remain pending.

Added the Workspace-scoped `metrics` module with an explicit two-binding allowlist (`net_revenue`, `variable_costs`) for the reviewed contribution-margin slice. `InputObservation` separates observed, unknown, not-applicable and invalid; zero remains a real Decimal value. Observations pin unit, currency, accounting basis, scope, half-open period, recorder, source identity/revision and an explanatory reason for non-observed states. They are immutable append-only records.

`InputObservationEvidence` requires same-Workspace available evidence, records the evidence revision and permission state at link time, and cannot be rewritten. `snapshot_inputs` rejects unsaved or duplicate bindings and any scope/period/currency/basis mismatch; it preserves source and evidence IDs/revisions/status without copying source prose. `CalculationRun` pins the exact metric, method revision, knowledge release/hash, variant, context and input trace; `MetricValue` preserves observed/unknown/not-applicable/invalid separately and both are immutable. No API or UI endpoint and no formula execution were added; 058-B owns the Decimal function and TS fixture parity.

Compatibility/rollback: migrations `metrics.0001` and `0002` add tables/trace fields only. Application rollback can hide the module while retaining records; table removal waits for real PostgreSQL backup/restore and export-parity checks.

Validation: combined `customer_context`, `evidence` and `metrics` suites pass 44/44 on temporary in-memory SQLite with migrations applied. Django system check and offline migration autodetection pass; Ruff E/F/I passes for the new module (pre-existing E501 style findings are excluded). ## STR-058-B — contribution amount and authorized persistence

Status: complete locally; Journey reuse, PostgreSQL/restore, server, Docker, browser/physical acceptance and remote merge remain pending.

Added the pure `calculate_contribution_amount` function and authorized `calculate_and_store_contribution_margin` service. It accepts only the two reviewed bindings and exact saved observation IDs, requires owner/editor access, validates current source/evidence permission and matching Workspace/scope/period/currency/accounting basis, and pins the exact `stratino-first-slice-v2` ID and content hash. It writes one immutable CalculationRun/MetricValue pair. Unknown/missing cost returns `unknown`; explicit not-applicable and invalid inputs remain distinct; zero and negative amounts are valid. Values use fixed six-decimal precision with no silent rounding. The owner-declared `cost_scope` is stored with the variable-cost observation and run; the system does not classify expenses or infer applicability.

`stratino-first-slice-v1` remains byte-for-byte historical and definition-only. New `stratino-first-slice-v2` enables only `typed_calculation_only`, with no raw business-type/stage tags. The shared `docs/fixtures/contribution-margin.json` drives Python Decimal and TypeScript BigInt previews for standard/zero/negative/fractional results, unknown/not-applicable, currency/period/scope/basis mismatches, missing policy, non-finite input and precision overflow. No eval path or production API/UI endpoint was added.

Compatibility/rollback: migration `metrics.0003` adds cost-scope text fields. Both knowledge releases are immutable package artifacts inside the existing API context; source KB files are unchanged. Code rollback retains records and both exact release IDs; destructive table removal waits for real PostgreSQL backup/restore and export-parity checks.
