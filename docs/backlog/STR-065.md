# STR-065 — برش عمودی استارتاپ از شناخت تا اقدام در داشبورد

Priority: **P1** | Epic: **MOS-SLICE** | Status: planned. Dependencies: STR-064, STR-027, STR-026.

## Context / Problem

Separate engines are not proof of a usable Management OS; first slice must use persistent real records end to end.

## Goal / User value

Integrate initial assessment, stage hypothesis, goals/problem and canonical ICP, one contribution calculation, retention evidence diagnostic and next action. The manager reuses trustworthy business information and reaches a defensible next action with less repeated input.

## Scope / Functional requirements

- Integrate initial assessment, stage hypothesis, goals/problem and canonical ICP, one contribution calculation, retention evidence diagnostic and next action.
- Reuse STR-027 dashboard and STR-021 decision/action records; no duplicate dashboard or goal store.
- Instrument synthetic and observed validation separately; prevent promotion beyond explicitly reviewed KB scope.

## Non-goals

No new hosting, paid services, generic workflow DSL, graph database, arbitrary health score or opaque AI decision logic. Preserve legacy tools; no unrelated domain expansion. Do not rebuild the design system.

## Domain impact / Data requirements

Follow the ownership and contracts in [ARCHITECTURE](../management-os/ARCHITECTURE.md). Workspace ID and explicit venture/segment/period context, revision, canonical references and provenance are required. No second ICP/revenue/Goal copy. Any persistence/schema change needs an explicit version and compatibility/rollback plan before apply.

## Knowledge-base dependencies

- `assets/management-knowledge/journeys/startup/journey.json`
- `assets/management-knowledge/validation/personas.json`
- `assets/management-knowledge/metrics/finance/met-contribution-margin.json`

## UX requirements / Accessibility

Read `.agents/skills/frontend-design/SKILL.md`, docs/UX_STANDARD.md and the existing system design before implementation. Write/review the design plan; reuse Vazirmatn/tokens/primitives and account preferences. Test keyboard/focus/labels, 200% zoom, reduced motion, fa/en RTL/LTR, light/dark, 360/768/1280/1440. Include loading, empty, invalid, unknown, permission, conflict and retry states; critique real screenshots.

## AI involvement / Deterministic logic

AI has no authority in this task. Reviewed IDs, versions, permissions, derivation, formulas, gates and completion are deterministic; source prose is never eval-executed. Any later AI wording is a reviewable draft outside this scope.

## Security / Privacy

Enforce server-side membership and same-Workspace nested references on all reads/writes/import/export/jobs. Viewer cannot write; revoked membership loses access. Use redacted logs, minimal personal data and revision/idempotency protections.

## Acceptance criteria

- [ ] Given persona B with supplied scoped evidence, refresh preserves the same metric, candidate, decision and action on dashboard.
- [ ] Given persona A without revenue, offer discovery/evidence action without CAC/LTV/ROIC or fake financial values.
- [ ] Given a viewer or foreign Workspace, no write or data leak; disabling new routes preserves existing tools.

## Test cases

- End-to-end A/B, no duplicate ICP/Goal/revenue, partial inputs, session expiry, refresh, rollback flag; C–F regression routing checks and real observed pilot queued.

Persona fixtures A (solo idea/no revenue), B (SaaS/10 staff/20 paying customers), C (ecommerce/50 staff), D (service SME/80 staff/low profit), E (manufacturing/300 staff/inventory), F (enterprise/2000 staff/execution) are context contracts, not observed user research. Apply relevant positive/negative cases and assert irrelevant inputs are suppressed.
