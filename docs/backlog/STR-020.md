# STR-020 — محاسبه EFE/IFE و نمایش تفسیر معتبر

اولویت: **P1** | ترتیب پیشنهادی: **20** | مرحله: **MVP** | مسیر: **strategy/calculation** | ریسک: **بالا**
وضعیت: توسعه انجام شده؛ آزمون‌های API، مرورگر، migration/Docker و بررسی تصویری برای اعتبارسنجی پایانی کل سیستم نگه داشته شده‌اند. وابستگی‌ها: [STR-018 / #18](https://github.com/Hamrez95/StrategicManagementPanel/issues/18).

## زمینه، اثر و شواهد

محصول استراتینو برای مدیر چند پروژه و مدیر/بنیان‌گذار فارسی‌زبان است. خط پایه فعلی پروتوتایپ localStorage است؛ auth، tenant isolation، paid billing و بایت فایل واقعی ندارد. قابلیت‌های محاسبات، آموزش و زبان موجود باید طبق جدول parity حفظ شوند.
این تسک یک بخش محدود از مسیر تحلیل→تصمیم→اجرا→مدارک است؛ scope زیر نتیجه قابل تحویل را تعریف می‌کند. ریسک‌های SaaS فرض امنیت فعلی نیستند؛ شرط ساخت نسخه جدیدند. اطمینان درباره خط پایه زیاد و درباره قیمت/تقاضای بازار پایین است.

## محدوده اجرا

- منطق EFE/IFE را با fixtures فعلی به TS و سرویس authoritative منتقل کن
- weight/rating، جمع وزن، rounding، داده ناقص و evidence را validate کن
- method version، input و output را ذخیره و تفسیر/محدودیت مدل را نمایش بده

## UI/UX ویژه این تسک

- جدول ورودی خوانا، نتیجه همراه داده ناقص و محدودیت
- نمودار جای جدول قابل دسترسی را نمی‌گیرد
- در هر رابط مرتبط: RTL/LTR، اعداد locale، روشن/تیره، ۳۶۰/۷۶۸/۱۲۸۰/۱۴۴۰، focus/keyboard، خوانایی، reduced-motion و loading/empty/error/success بررسی شود.
- در بک‌اند/زیرساخت: خطا، permission، limit و وضعیت ذخیره قابل نمایش در UI تعریف شود؛ ساخت صفحه تزئینی لازم نیست.

## اعتبارسنجی

golden fixtures، invalid/boundary values و API/client parity
فرمان دقیق پس از ایجاد زیرساخت در STR-007/008 ثبت می‌شود. برای prototype فعلی: npm run check، npm test و npm run build. تست مرورگر پس از localhost؛ اجرای ناموفق/اجرانشده را موفق گزارش نکن. آزمون متناسب با ریسک اجرا شود؛ permission/payment/migration آزمون منفی الزامی دارند.

در پایان توسعه STR-020، golden fixture مشترک، تست‌های domain/API و سناریوی مرورگر برای ماندگاری بعد از refresh، جداسازی Workspace، نقش viewer، خطای revision و نهایی‌سازی authored شده‌اند؛ هیچ‌کدام هنوز اجرا نشده‌اند. اجرای migration و Docker/server و screenshotهای RTL/LTR در دور اعتبارسنجی نهایی کل سیستم انجام می‌شود. جزئیات روش، نسخه و گرد کردن در [یادداشت طراحی](../design/STR-020-efe-ife.md) آمده است.
