# STR-054 — بارگذار نسخه‌دار و ترفیع صریح رکوردهای دانش

Priority: **P0** | Epic: **MOS-KNOWLEDGE** | Status: in_progress; packets A–C complete locally, D pending. Dependencies: STR-053.

## Context / Problem

Research formats/tags are heterogeneous and cannot be treated as executable definitions.

## Goal / User value

Define immutable release manifest with file hash, record revision, adapter and approved IDs; preserve raw research. The manager reuses trustworthy business information and reaches a defensible next action with less repeated input.

## Scope / Functional requirements

- Define immutable release manifest with file hash, record revision, adapter and approved IDs; preserve raw research.
- Explicit adapters for selected research shapes/versions; reject unknown versions/operators/tags; no heuristic coercion.
- Promote only first-slice discovery/retention routes and contribution metric after claim-to-source review; expose read-only registry to Django services.

## Non-goals

No new hosting, paid services, generic workflow DSL, graph database, arbitrary health score or opaque AI decision logic. Preserve legacy tools; no unrelated domain expansion. No decorative UI or invented production endpoint is required.

## Domain impact / Data requirements

Follow the ownership and contracts in [ARCHITECTURE](../management-os/ARCHITECTURE.md). Public KB only; never ingest company observations into public research. Any persistence/schema change needs an explicit version and compatibility/rollback plan before apply.

## Knowledge-base dependencies

- `assets/management-knowledge/taxonomy/applicability-contract.json`
- `assets/management-knowledge/taxonomy/field-mapping.json`
- `assets/management-knowledge/research/deferred-concepts.json`

## UX requirements / Accessibility

Return actionable bounded errors with affected IDs/fields; do not leak evidence or require managers to understand engine internals. When surfaced in UI, unknown/invalid/stale states need text and keyboard-accessible explanation, not color alone.

## AI involvement / Deterministic logic

AI has no authority in this task. Reviewed IDs, versions, permissions, derivation, formulas, gates and completion are deterministic; source prose is never eval-executed. Any later AI wording is a reviewable draft outside this scope.

## Security / Privacy

Knowledge files are public content only; reject path traversal/symlink escape, unknown shapes and unapproved runtime promotion. No external paid extraction.

## Acceptance criteria

- [ ] Given version 99 or unmapped platform applicability, record is rejected with a bounded error and no guessed behavior.
- [ ] Given PLAN-* research or unreviewed activation definition, it is excluded from executable registry.
- [ ] Given a historical run pinned to release A, loading release B never changes its stored meaning.

## STR-054-A — release contract and reader

Status: in_progress; packet A is implemented locally. No runtime release is promoted yet.

Added a pure-Python reader under `apps/api/modules/knowledge/`. Release schema v1 pins exact release ID, source KB commit, canonicalization version, full-manifest SHA-256, builder identity, sorted approved/source IDs, rejected-record diagnostic codes, and per-record source schema/revision/adapter/support/definition. The reader checks duplicate JSON keys, unsupported release versions/shapes, hash mismatch, source references, exact approved-record set, file size, and package-path containment. It returns deeply immutable records and has no `latest` fallback, Django/model, network or research-tree dependency. Canonical hashing is compact sorted-key UTF-8 JSON, with CRLF/LF and whitespace-independent integrity.
