# STR-068 — تکمیل شکاف پژوهش و بازبینی ادعا در منابع اصلی

Priority: **P2** | Epic: **MOS-KNOWLEDGE** | Status: planned. Dependencies: STR-053.

## Context / Problem

KB is a bounded research foundation; many requested domains and claim-level source checks remain incomplete.

## Goal / User value

Prioritize one domain per small research batch; map each claim to inspected source sections and access depth, preserve competing findings. The manager reuses trustworthy business information and reaches a defensible next action with less repeated input.

## Scope / Functional requirements

- Prioritize one domain per small research batch; map each claim to inspected source sections and access depth, preserve competing findings.
- Review activation source, TOWS/Ansoff, local finance, sales/people/operations and AI gaps only from primary sources; never promote metadata-only detail.
- Update canonical records/indices/status and domain fixtures; expert/user outcome evidence remains distinct from structural coverage.

## Non-goals

No new hosting, paid services, generic workflow DSL, graph database, arbitrary health score or opaque AI decision logic. Preserve legacy tools; no unrelated domain expansion. No decorative UI or invented production endpoint is required.

## Domain impact / Data requirements

Follow the ownership and contracts in [ARCHITECTURE](../management-os/ARCHITECTURE.md). Public KB only; never ingest company observations into public research. Any persistence/schema change needs an explicit version and compatibility/rollback plan before apply.

## Knowledge-base dependencies

- `assets/management-knowledge/research/deferred-concepts.json`
- `assets/management-knowledge/research/conflicting-evidence.md`
- `assets/management-knowledge/NEXT_ACTIONS.md`

## UX requirements / Accessibility

Return actionable bounded errors with affected IDs/fields; do not leak evidence or require managers to understand engine internals. When surfaced in UI, unknown/invalid/stale states need text and keyboard-accessible explanation, not color alone.

## AI involvement / Deterministic logic

AI has no authority in this task. Reviewed IDs, versions, permissions, derivation, formulas, gates and completion are deterministic; source prose is never eval-executed. Any later AI wording is a reviewable draft outside this scope.

## Security / Privacy

Knowledge files are public content only; reject path traversal/symlink escape, unknown shapes and unapproved runtime promotion. No external paid extraction.

## Acceptance criteria

- [ ] Given inaccessible original content, item remains deferred with exact missing evidence.
- [ ] Given a changed metric definition, new semantic revision and dependent migration/fixtures are required.
- [ ] Given conflicting sources, both contexts and implications remain visible; no fabricated benchmark or citation closes the gap.

## Test cases

- Source ID/URL/claim trace, duplicate concept/alias, regression fixtures, explanation levels, context applicability and promotion-review checklist.

Persona fixtures A (solo idea/no revenue), B (SaaS/10 staff/20 paying customers), C (ecommerce/50 staff), D (service SME/80 staff/low profit), E (manufacturing/300 staff/inventory), F (enterprise/2000 staff/execution) are context contracts, not observed user research. Apply relevant positive/negative cases and assert irrelevant inputs are suppressed.
