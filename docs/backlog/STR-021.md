# STR-021 — دفتر تصمیم و برنامه اجرای قابل پیگیری

اولویت: **P1** | ترتیب پیشنهادی: **21** | مرحله: **MVP** | مسیر: **execution** | ریسک: **متوسط**
وضعیت: توسعه انجام شده؛ آزمون‌های API، مرورگر، migration/Docker و بررسی تصویری برای اعتبارسنجی پایانی کل سیستم نگه داشته شده‌اند. وابستگی‌ها: [STR-019 / #19](https://github.com/Hamrez95/StrategicManagementPanel/issues/19), [STR-020 / #20](https://github.com/Hamrez95/StrategicManagementPanel/issues/20).

## زمینه، اثر و شواهد

محصول استراتینو برای مدیر چند پروژه و مدیر/بنیان‌گذار فارسی‌زبان است. خط پایه فعلی پروتوتایپ localStorage است؛ auth، tenant isolation، paid billing و بایت فایل واقعی ندارد. قابلیت‌های محاسبات، آموزش و زبان موجود باید طبق جدول parity حفظ شوند.
این تسک یک بخش محدود از مسیر تحلیل→تصمیم→اجرا→مدارک است؛ scope زیر نتیجه قابل تحویل را تعریف می‌کند. ریسک‌های SaaS فرض امنیت فعلی نیستند؛ شرط ساخت نسخه جدیدند. اطمینان درباره خط پایه زیاد و درباره قیمت/تقاضای بازار پایین است.

## فایل‌ها و مسیر بررسی

`apps/api/modules/execution/; apps/web/src/features/decisions/; apps/web/src/api/contracts.ts; docs/api/openapi.json; docs/design/STR-021-execution.md; scripts/verify-web.mjs`
مسیرهای apps/packages/infra پیشنهادی‌اند و در STR-003 ایجاد می‌شوند؛ وجود فعلی آن‌ها ادعا نمی‌شود. نام فایل catalog فعلی را با Graphify پیدا کن، نه با فرض.

## Graphify و مهارت‌ها — در این تسک اجباری

`graphify --version`؛ گراف اولیه `graphify . --code-only --no-viz` یا در تغییر کد `graphify update .`.
Query نخست: `graphify query "دفتر تصمیم و برنامه اجرای قابل پیگیری apps/api/modules/execution/; apps/web/src/features/decisions/; actions board dependencies consumers tests" --budget 1200`.
اگر query فارسی نتیجه نداد با نماد/نام فایل بالا query یا explain انجام بده، سپس rg محدود. بعد تغییر کد graph را update و مصرف‌کنندگان را بررسی کن؛ تحلیل اسناد با LLM یا Cloud پولی خودکار فعال نشود.
برای طراحی/تغییر UI، [.agents/skills/frontend-design/SKILL.md](https://github.com/Hamrez95/StrategicManagementPanel/blob/docs/stratino-execution-plan/.agents/skills/frontend-design/SKILL.md) را بخوان و طرح/نقد را انجام بده. [گردش توسعه](https://github.com/Hamrez95/StrategicManagementPanel/blob/docs/stratino-execution-plan/docs/DEVELOPMENT_WORKFLOW.md) و [قرارداد UI/UX](https://github.com/Hamrez95/StrategicManagementPanel/blob/docs/stratino-execution-plan/docs/UX_STANDARD.md) در این issue لازم‌الاجرا هستند. مهارت‌های مرتبط دیگر طبق دامنه اعمال شوند؛ اجرای مهارت ناموجود ادعا نشود.

## محدوده اجرا

- Decision با دلیل، فرض، منبع تحلیل و trigger review بساز
- Action با owner عضو پروژه، موعد، status و هدف مرتبط پیاده کن
- نمای برنامه ۹۰روزه و history تغییرات داشته باشد؛ task manager عمومی و chat خارج محدوده

## UI/UX ویژه این تسک

- kanban با کیبورد و گزینه تغییر وضعیت بدون drag
- وضعیت عقب‌افتاده با متن و تاریخ روشن، نه فقط قرمز
- در هر رابط مرتبط: RTL/LTR، اعداد locale، روشن/تیره، ۳۶۰/۷۶۸/۱۲۸۰/۱۴۴۰، focus/keyboard، خوانایی، reduced-motion و loading/empty/error/success بررسی شود.
- در بک‌اند/زیرساخت: خطا، permission، limit و وضعیت ذخیره قابل نمایش در UI تعریف شود؛ ساخت صفحه تزئینی لازم نیست.

- [ ] معیارهای مرتبط UX_STANDARD پاس شده یا blocker دقیق ثبت شده؛ Done صرفاً با ساخته‌شدن فایل یا دکمه نیست.

## اعتبارسنجی

CRUD/link/role و timezone/due date؛ board keyboard
فرمان دقیق پس از ایجاد زیرساخت در STR-007/008 ثبت می‌شود. برای prototype فعلی: npm run check، npm test و npm run build. تست مرورگر پس از localhost؛ اجرای ناموفق/اجرانشده را موفق گزارش نکن. آزمون متناسب با ریسک اجرا شود؛ permission/payment/migration آزمون منفی الزامی دارند.

سرویس API و migration، تست‌های API برای Workspace/role/منبع/عضویت/تاریخ/تعارض/history، قراردادهای OpenAPI و سناریوی مرورگر برای اتصال تحلیل→تصمیم→هدف→اقدام، refresh، RTL/LTR، theme، breakpoint و keyboard نوشته شده‌اند. این تست‌ها اجرا نشده‌اند؛ اجرای آن‌ها، migration/Docker و screenshot در دور اعتبارسنجی نهایی کل سیستم انجام می‌شود. طرح رابط و قواعد تاریخ و تخصیص در [یادداشت طراحی](../design/STR-021-execution.md) آمده است.

## مرز، تحویل و بازگشت
