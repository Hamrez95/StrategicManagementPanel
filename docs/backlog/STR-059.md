# STR-059 — ارزیابی زمینه و طبقه‌بندی مرحله با حفظ unknown

Priority: **P1** | Epic: **MOS-JOURNEY** | Status: planned. Dependencies: STR-054, STR-056, STR-057.

## Context / Problem

Reported stage/headcount is not an evidence-backed lifecycle or maturity assessment.

## Goal / User value

Map existing profile axes with explicit unknown/conflict states; support venture/segment scope inside established businesses. The manager reuses trustworthy business information and reaches a defensible next action with less repeated input.

## Scope / Functional requirements

- Map existing profile axes with explicit unknown/conflict states; support venture/segment scope inside established businesses.
- Produce provisional/supported/conflicted/unknown assessment with reviewed evidence and rationale; manual override requires reason/reviewer/expiry.
- Reuse imports/profile and ask only context that changes routing; no mandatory financial questionnaire.

## Non-goals

No new hosting, paid services, generic workflow DSL, graph database, arbitrary health score or opaque AI decision logic. Preserve legacy tools; no unrelated domain expansion. Do not rebuild the design system.

## Domain impact / Data requirements

Follow the ownership and contracts in [ARCHITECTURE](../management-os/ARCHITECTURE.md). Workspace ID and explicit venture/segment/period context, revision, canonical references and provenance are required. No second ICP/revenue/Goal copy. Any persistence/schema change needs an explicit version and compatibility/rollback plan before apply.
