# First vertical slice — reviewed startup decisions

## Outcome and boundaries

A founder can understand a scoped situation, inspect one justified next action, accept a decision/action and find it on the operating dashboard after refresh. This validates the architecture before expanding every engine. It is not an autonomous management adviser or a new questionnaire product.

Primary persona B: SaaS, 10 employees, 20 paying customers, early traction, material acquisition expansion requested, insufficient cohort evidence. Counterexample A: solo idea-stage/no revenue; do not demand financial ratios. Start with explicit user-reported context; an assessed stage remains provisional until required evidence is reviewed.

## Persisted flow

1. Select existing Workspace and venture/segment context. Reuse profile, products, goal and ICP; preserve free text/legacy records through the migration adapter.
2. Short initial assessment distinguishes model search from operating execution; employee count does not assign stage. Imported verified fields suppress questions.
3. Clarify problem/goal and one ICP evidence gap only if unresolved. Guided mode offers quick/learn/deep and previous/next; expert mode offers compact import/skip/defer. show_tutorial remains global.
4. Reuse or collect net_revenue and variable_costs with explicit cost policy, period, currency and accounting basis. Calculate **MET-CONTRIBUTION-MARGIN amount** via the reviewed server function. Example 100−60=40 is synthetic, not a business benchmark. If inputs are absent or incompatible, result is unknown/invalid, never zero.
5. Evaluate reviewed RULE-RETENTION-BEFORE-SCALE using scope-matched cohort/evidence state. Limited bounded experiments and one-off value models retain the declared exceptions. No PMF score or causal churn diagnosis is asserted.
6. Show candidate REC-RETENTION-BEFORE-SCALE with Why, evidence/metric context, insufficient/low confidence reasons, limitations, risks, alternatives and sources. The contribution calculation is useful context, **not an invented threshold/trigger for the retention rule**.
7. User accepts an evidence-gathering next action, names owner/date and, where needed, a proposed Decision. Existing execution entities are reused; retries create one record. KPI/cohort observation binding is optional unless supported by actual data. Do not fabricate cohort values or a new experimental result.
8. STR-027 dashboard displays saved situation/attention/action and unresolved data; refresh/Workspace switching preserve the same canonical IDs. Review records outcomes and re-evaluates pinned evidence in a new run.

## Prove before expanding

Automated: A/B positive and negative flows; canonical ICP/Goal/metric identity across modules; null/zero/currency/period; viewer/foreign/revoked membership; revision conflict; idempotent acceptance; release pinning; imported data conflict; skip blocks only dependent commitments; historical snapshots remain immutable. C/D/E/F must not receive irrelevant startup/financial questions merely because their model is unknown.

Browser/physical final queue: fa/en, RTL/LTR, light/dark/system, both modes, global education off, keyboard/focus, reduced motion, 200% zoom, four widths; actual local API/Postgres persistence/migration and runner; observed founder/manager session with consent and non-sensitive data. Measure time, repeated questions, ability to explain uncertainty and reach a next action; no invented target success result.

Release: feature/route boundary off by default until acceptance. Existing tools continue via existing paths. Failure to validate the slice blocks scope expansion, not access to already working tools. Required tests remain pending until real execution; task closure follows merge and evidence.
