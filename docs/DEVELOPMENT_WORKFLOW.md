# اجرای تسک با کیفیت و مصرف توکن کنترل‌شده

## شروع هر تسک

۱. AGENTS.md، تسک انتخاب‌شده، وابستگی‌ها و فقط سند مرتبط را بخوان. کار خارج از محدوده را جدا ثبت کن.
۲. `git status --short` و ref پایه را بررسی کن. تسک را صرفاً به‌دلیل موجودبودن یک دکمه Done نکن.
۳. `graphify --version`؛ اگر ابزار در PATH نیست، مسیر نصب‌شده uv یا `uv tool run --from graphifyy==0.9.89 graphify` را استفاده کن.
۴. اولین بار: `graphify . --code-only --no-viz`؛ در کد تغییرکرده: `graphify update .`؛ سپس query دقیق با `--budget 1200` و در صورت نیاز path/explain.
۵. فقط فایل‌ها و مصرف‌کنندگان معرفی‌شده را با rg و خواندن محدوده خط بررسی کن. برای تسک مستندات/طراحی، graphify نقشه کد می‌دهد؛ جای خواندن brief مرتبط را نمی‌گیرد.
۶. UI: frontend-design و UX_STANDARD را اعمال کن. تحلیل معماری: روش lifecycle-architecture-review. مهارت نصب‌نشده را اجراشده اعلام نکن و مهارت نامرتبط را صرفاً برای زیادشدن تعداد مهارت‌ها نخوان.

## حدود هزینه و کیفیت

Graphify در حالت code-only و update تحلیل AST محلی است؛ extraction اسناد/تصاویر یا label با LLM، Cloud، API key و پلن پولی را خودکار فعال نکن. درصد کاهش توکن برای این مخزن اندازه‌گیری نشده است.
خواندن کل graph.json یا کل src/app.js در هر تسک ممنوع؛ اگر query نتیجه ندارد با rg هدفمند ادامه بده و علت را ثبت کن. فایل‌های graph محلی قابل بازسازی‌اند و در gitignore هستند؛ skill و دستورالعمل نصب در ریپو ثبت می‌شوند.
یک تسک، یک تغییر منسجم و PR قابل بررسی. آزمون متناسب با ریسک؛ auth، billing و migration حتماً آزمون منفی دارند. build طولانی نامرتبط تکرار نشود؛ blocker مستند و کار مستقل ادامه داده شود.
تغییر داده حساس، معماری چندمستاجری، پرداخت و migration را در PR مستقل با rollback و شواهد بررسی ارائه کن. کد تکراری UI را می‌توان به مدل سبک سپرد؛ صحت امنیت را به حدس یا تست نمایشی نسپار.

## پایان

پیش از merge، منتظر پایان آخرین فرآیند بررسی بمان و exit code را صریحاً صفر بررسی کن. پاس‌شدن build یا بخشی از خروجی، موفقیت کل pipeline نیست. نتیجه ناموفق یک tool call نباید با ادامه خودکار عملیات merge پوشانده شود؛ ابتدا خطا را اصلاح و بررسی مرتبط را کامل کن.

`graphify update .` بعد از تغییر کد، query مصرف‌کنندگان، بررسی diff، آزمون‌های مرتبط و ثبت نتیجه واقعی. PR به شماره issue وصل باشد؛ closure فقط پس از ادغام تغییر کامل و پاس‌شدن معیارهای پذیرش. ایجاد issue با اجرای آن متفاوت است.
خرید سرویس، تغییر نام مخزن در GitHub، حذف شاخه، merge و deploy خودکار از دستور این فایل نتیجه نمی‌شود؛ دامنه مجوز کاربر و قواعد پروژه را رعایت کن.

## اعتبارسنجی خط پایه و آینده

فعلی: `npm run check`، `npm test`، `npm run build`؛ تست مرورگر بعد از localhost با `npm run test:browser`.
پس از STR-003/007: اسکریپت‌های workspace برای lint/typecheck/test/build و `python manage.py test` یا pytest مطابق تنظیم واقعی پروژه. STR-007 نام دقیق فرمان‌ها را ثبت می‌کند؛ موفقیت فرمانی که هنوز وجود ندارد ادعا نشود.

## نصب قابل تکرار ابزار

Graphify تأییدشده این جلسه: `graphifyy==0.9.89`؛ `uv tool install graphifyy==0.9.89` سپس `graphify install --project --platform codex`.
نسخه skill تولیدشده در `.codex/skills/graphify/` ثبت می‌شود. نصب دوباره ممکن است AGENTS.md و hook را تغییر دهد؛ diff آن را بررسی کن. hook-check این نسخه برای Codex راهنمای عملی query را جایگزین نمی‌کند.
frontend-design از commit ثبت‌شده در SOURCE.md نصب شده است. به‌روزرسانی منابع بالادستی فقط با بررسی diff و مجوز انجام شود؛ اجرای خودکار کد نامطمئن یا نصب latest در هر تسک لازم نیست.
