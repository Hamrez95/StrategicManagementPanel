# آماده‌سازی محتوا برای چند زبان

متن فارسی همچنان منبع اصلیه. پوشهٔ `en` قالب خالی ترجمه‌ست؛ وجودش به معنی آماده‌بودن آموزش انگلیسی نیست. در این مرحله انتخاب زبان به رابط اضافه نشده.

## قرارداد ترجمه

- خروجی `scripts/export_locales.py` متن‌های آموزشی، هدف‌ها، مثال‌ها، پرسش‌ها، گزینه‌ها، بازخوردها، جدول‌ها، راهنمای فعالیت، کاتالوگ و متنِ منبعِ تصویرها رو از داده‌های ساختاری جدا می‌کنه.
- کلید هر متن از شناسهٔ درس، کارت، سؤال و گزینه ساخته می‌شه. برای ردیف‌های بدون شناسه، شمارهٔ ردیف هم دخیل می‌شه؛ بعد از جابه‌جایی ردیف‌ها، ترجمه باید دوباره بررسی بشه.
- `pointer` نشانی متن در سند منبعه و قواعد JSON Pointer رو رعایت می‌کنه؛ `source_hash` تغییر خود متن و `source_revision` تغییر سند رو مشخص می‌کنن. ترجمهٔ مربوط به نسخهٔ قبلی نباید خودکار اعمال بشه. برای سند مرحله، `revision_excluded_fields` مشخص می‌کنه که نسخهٔ منبع بدون درس‌های جاسازی‌شده محاسبه شده.
- در هر سند مقصد، فقط پیام‌های ترجمه‌شده رو با همون کلید، هش منبع و نشانی ثبت کن. شناسه‌ها و نوع دادهٔ داخل معیارهای ارزیابی هم وارد واحدهای ترجمه نمی‌شن. سلولِ صرفاً عددی و فرمول مستقل از خروجی ترجمه کنار گذاشته می‌شن. برچسب واحد، خروجی مورد انتظار و توضیح بلند تصویر قابل ترجمه‌ان. شناسه، پاسخ درست، مقدار عددی، فرمول، نمره و نشانی منابع ترجمه نمی‌شن. عددها و واحدهای داخل مثال هم باید با محاسبه سازگار بمونن.
- اگر ترجمهٔ کامل یک سند موجود نیست، کل سند با زبان و جهت فارسی نمایش داده بشه؛ متن فارسی رو داخل ظرف انگلیسی و چپ‌چین نذار. عبارت انگلیسی و فرمول داخل فارسی به جداسازی جهت نیاز دارن.
- شکل‌های مفهومی از `content/media/visuals.v1.json` ساخته می‌شن. ترجمهٔ متن منبع تصویر باید به خروجی SVG تازه منجر بشه. ۲۶ شکل تخصصی هنوز متن داخل SVG دارن و برای ترجمه به بازچینی و کنترل مقیاس نیاز دارن؛ تصویر فارسی رو ترجمه‌شده حساب نکن.
- متن‌های رابط محیط مرور هنوز داخل `editor-preview.js` هستن و برای انتقال به اپ اصلی باید به کلیدهای معنایی رابط مقصد وصل بشن. این مرحله آماده‌سازی بستهٔ آموزشیه، نه تکمیل رابط چندزبانه.

## فونت

منبع واحد تنظیم فونت: `public/typography/typography.css` در ریشهٔ ریپو.

- `--font-ui`: فونت رابط کل اپ.
- `--font-content`: فونت محتوای آکادمی، درسنامه‌ها و تصویرهای آموزشی.
- `--font-code`: فونت مناسب کد و دادهٔ فنی.

پیش‌فرض هر دو بخش فارسی، **Vazir 30.1.0** با وزن معمولی و ضخیمه؛ فایل فونت و مجوز کنار پروژه نگهداری می‌شن. این همون وزیره؛ وزیرمتن قبلی جایگزین اسمش نشده. برای فونت تازه، فایل و `@font-face` رو اضافه کن و دو متغیر رو تغییر بده. فونت داخل متن درس یا هر صفحه جداگانه تعیین نشه.

بعد از تغییر تنظیم فونت، `scripts/build-preview.py` نسخهٔ محیط مرور رو همگام می‌کنه. برای تغییر فونتِ نوشته‌های داخل SVG، `scripts/build_educational_visuals.py` رو هم اجرا کن؛ فونت تصویر از CSS صفحه به ارث نمی‌رسه و در زمان تولید داخل تصویر قرار می‌گیره. برای زبان‌های بعدی، پوشش حروف فونت، جهت متن، شکستن خط‌ها و فرمول‌ها دوباره بررسی بشه.

## ترتیب بازتولید

۱. ویرایش منبع اصلی درس یا تصویر و بازبینی معنی، پاسخ و محاسبه.
۲. اجرای سازندهٔ شکل‌ها در صورت تغییر تصویر یا فونت.
۳. اجرای `scripts/build-preview.py` برای همگام‌سازی بسته‌ها و محیط مرور.
۴. اجرای `scripts/export_locales.py` برای به‌روزرسانی واحدهای ترجمه؛ این دستور ترجمه‌های مقصد موجود رو بازنویسی نمی‌کنه.

راهنمای [لحن](../../CONTENT_STYLE_FA.md) و [سبک آموزشی تصویر](../CONTENT_VISUAL_STYLE_FA.md) برای تولید و ترجمهٔ آینده هم مبنا هستن.

پیش از ساخت فهرست انتقال، `scripts/audit_review_reuse.py` و بعد سازندهٔ صفحه و خروجی ترجمه اجرا بشن؛ در آخر `scripts/prepare_ui_handoff.py` هش نسخهٔ قابل تحویل رو ثبت می‌کنه. بعد از هر ویرایش محتوا، این فهرست باید تازه بشه.
