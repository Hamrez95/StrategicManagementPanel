# دفتر تصمیم‌های محصول و معماری

این پوشه مرجع تصمیم‌های پایدار محصول، آموزش و معماری است. هر تصمیم مهم یک فایل مستقل ADR دارد تا هنگام طراحی و پیاده‌سازی، فرض‌های قدیمی دوباره ساخته نشوند.

## روش ثبت

- تصمیم نهایی با وضعیت «قطعی» ثبت می‌شود.
- قیمت‌ها و جهت‌هایی که هنوز با کاربر یا بازار اعتبارسنجی نشده‌اند، «فرضیه» می‌مانند.
- موضوعات حل‌نشده با وضعیت «باز» ثبت می‌شوند؛ گزینه‌ها را به‌جای تصمیم قطعی نشان نمی‌دهیم.
- تغییر تصمیم قطعی با ADR تازه و ارجاع به تصمیم قبلی ثبت می‌شود؛ تاریخچه بی‌صدا بازنویسی نمی‌شود.
- دفتر نوشن برای جست‌وجو و پیگیری است؛ این فایل‌ها مرجع قابل‌استفاده برای پیاده‌سازی هستند.
