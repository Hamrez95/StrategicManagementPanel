# آمادگی استراتینو پیش از خرید سرور

تاریخ بررسی: ۱۰ آبان ۱۴۰۵ / 2026-11-01

این بسته برای آماده‌سازی پیش از خرید سروره. به درخواست مالک، روی سیستم شرکت هیچ بررسی وابسته به اجرای Docker انجام نمی‌شه. ساخته‌شدن فایل‌های سرور به معنی تأیید اجرای اون‌ها یا آماده‌بودن محصول برای کاربر واقعی نیست.

## کارهای قابل انجام بدون خرید

| کار | تحویل |
| --- | --- |
| فایل‌های انتشار وب و API | `infra/Dockerfile.web` و `infra/Dockerfile.api`؛ محتوای مرجع خصوصی آموزش در API می‌مونه. |
| تنظیم سرویس‌های سرور آینده | `infra/compose.production.yml`؛ شبکهٔ خصوصی، فضای پایدار، محدودیت حافظه، گردش لاگ و راه‌اندازی مجدد. |
| دامنه، HTTPS و مسیریابی | `infra/Caddyfile`؛ وب و API زیر یک دامنه، مسیر مدیریت و فایل‌های استاتیک، جلوگیری از ارائهٔ فایل خصوصی. |
| ارتباط امن دیتابیس | پروفایل PostgreSQL با TLS برای یک سرور؛ مسیر استفاده از دیتابیس مدیریت‌شده در راهنما. |
| اصلاح تشخیص HTTPS و IP کاربر | اعتماد به پراکسی فقط با تنظیم صریح production؛ تست آدرس جعلی و حفظ IP کاربران مستقل. |
| قالب تنظیمات و تولید کلید | `infra/.env.production.example` و `scripts/prepare-production.mjs`؛ تولید کلید روی دستگاه مورد اعتماد، بدون چاپ رمز یا بازنویسی فایل قبلی. |
| بررسی آفلاین تنظیمات | `npm run check:deployment`؛ بدون اجرای Docker و بدون اتصال به سرویس خارجی. |
| بررسی پس از استقرار | `scripts/check-live-deployment.mjs`؛ بررسی فقط‌خواندنی HTTPS، سلامت، کوکی، نشست ناشناس و خطای مسیرهای نامعتبر. |
| پشتیبان و بازیابی | اسکریپت پشتیبان سرور لینوکسی و راهنمای بازیابی جدا از سرویس اصلی، کنار ابزار موجود بازیابی آزمایشی. |
| برنامهٔ انتشار و برگشت نسخه | راهنمای migration، ثبت نسخهٔ image، بازگشت سازگار و بازیابی دیتابیس و فایل در صورت ناسازگاری. |
| چک‌لیست عملیاتی | راهنمای پایش، هشدار، ایمیل، کلیدهای بازیابی و آزمون‌های لازم پیش از ورود کاربر واقعی. |

راهنمای دقیق و دستورهای مخصوص سرور آینده در [PRODUCTION.md](PRODUCTION.md) ثبت شده. دستورهای Docker اون راهنما روی این سیستم اجرا نمی‌شن.

## اطلاعاتی که بعداً باید مشخص بشن

- دامنهٔ نهایی و دسترسی DNS؛ قالب فعلی عمداً دامنهٔ نمونه داره.
- سرویس‌دهنده و محل میزبانی؛ دیتابیس مدیریت‌شده یا پروفایل یک سرور.
- سرویس ایمیل، آدرس فرستنده و تنظیم SPF/DKIM/DMARC طبق راهنمای همون سرویس.
- مقصد مستقل بکاپ رمزگذاری‌شده، کلید بازیابی، برنامهٔ نگهداری و بازهٔ قابل قبول از دست‌رفتن داده.
- مقصد دریافت هشدار و مسئول پاسخ‌گویی به قطعی.
- انتخاب صریح فعال‌بودن آموزش در انتشار اول؛ مقدار پیش‌فرض قالب `false` است.
- در صورت نیاز، تنظیم Google OAuth با دامنهٔ نهایی. ورود گوگل برای استقرار پایه الزامی نیست.

کلید و رمز واقعی production روی سیستم شرکت ساخته نشده. تولیدکنندهٔ امن و قالبش آماده است؛ کلیدهای نهایی باید روی دستگاه مورد اعتماد ساخته و در محل امن نگهداری بشن.

## مرز تأیید

اجرای imageها، اتصال واقعی PostgreSQL، اجرای migration روی دیتابیس، تست مرورگری جریان کامل حساب و Workspace، اسکن واقعی فایل، ارسال ایمیل و بازیابی دیتابیس باید در محیط آزمایشی مناسب انجام بشن. این کارها به درخواست مالک روی سیستم فعلی انجام نمی‌شن. هیچ‌کدوم از تسک‌های انتشار صرفاً با آماده‌شدن این فایل‌ها بسته نمی‌شن.

فروش اشتراک هم مرحلهٔ جداست: checkout فعلی غیرفعاله؛ ارائه‌دهندهٔ پرداخت و سیاست تجاری با این بسته فعال نمی‌شن.

## شواهد بررسی این نوبت

| بررسی | نتیجهٔ واقعی |
| --- | --- |
| `npm run quality` | موفق؛ lint، قالب‌بندی، typecheck، قراردادها، بررسی ساختار دانش، ۱۰۱ تست برنامه، ۱۸ تست domain و build. تست چهارم تنظیمات بعد از این اجرا اضافه و جداگانه پاس شد. |
| `npm run check:deployment` | موفق؛ ساختار فایل‌های انتشار و ۴ تست تنظیمات، از جمله جداسازی حساب مدیر دیتابیس از حساب برنامه. |
| تست‌های Python بدون دیتابیس | از ۱۷ تست، ۱۶ تست موفق و یک تست مربوط به symlink در ویندوز اجرا نشد؛ شامل پراکسی، مرز فایل خصوصی و ابزار snapshot. |
| `manage.py check --deploy --fail-level WARNING` | موفق با تنظیمات نمونهٔ production و کلیدهای موقت در حافظه؛ بدون اتصال به دیتابیس یا ارسال ایمیل. |
| منابع API و خروجی عمومی آموزش | بررسی منابع API و خروجی ۴۴ دوره موفق؛ کلید پاسخ وارد خروجی عمومی نشد. |
| نحو اسکریپت‌های Bash | با `bash -n` بررسی شد؛ خود اسکریپت‌های سرور اجرا نشدن. |
| بررسی diff | خطای whitespace دیده نشد. خطاهای اولیهٔ قالب‌بندی و projection از CRLF/LF بودن فایل‌های همین checkout بود؛ با یکسان‌سازی پایان‌خط رفع شد و تغییر محتوایی در رابط یا دانش ایجاد نشد. |
| بررسی آسیب‌پذیری وابستگی‌های npm | تأیید نشده؛ رجیستری سازمانی خطای 403 و درخواست رجیستری عمومی خطای اتصال داد. هیچ تنظیم رجیستری سیستم تغییر نکرد. |
| اجرای کامل محلی بدون Docker، پس از درخواست جدید مالک | PostgreSQL 17.11، API و Mailpit واقعی اجرا شدن؛ از ۴۰۵ تست API، ۴۰۴ تست موفق و یک تست symlink در ویندوز اجرا نشد. |
| جریان واقعی مرورگر و API | راهنما و ورود مدیر نمایش داده شدن؛ ثبت‌نام، تأیید ایمیل واقعی در صندوق محلی، ورود، ساخت Workspace، ذخیره و بازخوانی یادداشت و قطع دسترسی بعد از خروج بدون mock بررسی شدن. راهنما: `docs/LOCAL_NATIVE.md`. |
| Docker، Caddy/TLS واقعی و اسکن واقعی بدافزار | روی سیستم شرکت اجرا نشدن؛ همچنان نیازمند محیط آزمایشی مناسب هستن. |

پایتون بررسی محلی 3.11 و نسخهٔ هدف image سرور 3.12 است؛ موفقیت تست‌های محلی، ساخت و اجرای image رو اثبات نمی‌کنه. وابستگی‌های Python فقط در `.venv` همین پروژه نصب شدن و تنظیمات سیستمی تغییر نکردن.

گراف وابستگی‌های پروژه بعد از تغییر کد با حالت محلی `graphify update .` به‌روز می‌شه. هیچ استقرار عمومی، خرید سرویس، تغییر DNS، ارسال ایمیل خارجی یا ساخت کلید production انجام نشده. ایمیل‌های بررسی جدید فقط در Mailpit روی همین سیستم گرفته شدن.
